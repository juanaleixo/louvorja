# 🌐 Internacionalização (i18n)

O LouvorJA usa **Vue I18n** com uma única instância global. Tanto as chaves
globais (`/src/lang`) quanto as chaves de cada módulo (`src/modules/<id>/lang`)
são fundidas na **mesma instância** — não existem instâncias separadas por módulo.

## 🔀 Dois arquivos, um único namespace

| Origem | Caminho da chave | Exemplo |
|--------|------------------|---------|
| Global (`/src/lang/{pt,es}.json`) | raiz ou namespace (`actions`, `components`, `alert`, ...) | `actions.save`, `alert.yes` |
| Módulo (`src/modules/<id>/lang/{pt,es}.json`) | `modules.<id>.<key>` | `modules.scheduled_items.entry_title` |

O `ModuleManager` funde o lang do módulo em boot via:

```js
i18n.global.mergeLocaleMessage(lang, { modules: { [manifest.id]: translations } });
```

Como tudo está na mesma instância, **qualquer chave está acessível de qualquer
componente** — basta usar o caminho correto.

## 🧩 Como usar dentro de um módulo

Cada componente de módulo tipicamente faz:

```ts
import { useI18n } from "vue-i18n";
const { t } = useI18n();

// Helper de conveniência que prefixa o id do módulo:
function tt(key: string): string {
  return t(`modules.${manifest.id}.${key}`);
}
```

### Chaves do PRÓPRIO módulo → `tt("key")`

```vue
<v-btn>{{ tt("entry_title") }}</v-btn>   <!-- → modules.<id>.entry_title -->
```

`tt` resolve para `modules.<id>.<key>`, que vem do arquivo `lang` do módulo.

### Chaves GLOBAIS/compartilhadas → `t("namespace.key")`

```vue
<v-btn>{{ t("actions.save") }}</v-btn>     <!-- vem de /src/lang → "Salvar" -->
<v-btn>{{ t("actions.cancel") }}</v-btn>   <!-- vem de /src/lang → "Cancelar" -->
```

Chaves genéricas de UI (Salvar, Cancelar, Excluir, Editar, Fechar, etc.)
**já existem no global** sob o namespace `actions`. Prefira reusá-las em vez de
redefinir no lang do módulo.

## ⚠️ Regra anti-colisão

- O subtree `modules.<id>.*` é de **propriedade exclusiva do módulo** — declarado
  no `lang` do próprio módulo.
- **Não** defina `modules.<id>.*` no `/src/lang`. O global pode ter strings
  compartilhadas (ex.: `modules.invalid.title`), mas nunca a mesma chave que um
  módulo já define.
- Chaves locais devem ser referenciadas via `tt("key")`. Usar `t("key")` (sem
  namespace) **não resolve** a chave local — o `t` procura só na raiz e acaba
  exibindo o próprio nome da chave.

## ✅ Exemplo prático

```vue
<!-- CORRETO -->
<v-card-actions>
  <v-btn @click="save">{{ t("actions.save") }}</v-btn>     <!-- global -->
  <v-btn @click="cancel">{{ t("actions.cancel") }}</v-btn> <!-- global -->
</v-card-actions>
<v-card-text>{{ tt("entry_title") }}</v-btn>               <!-- local -->
<span>{{ tt("choose_file") }}</span>                      <!-- local -->

<!-- INCORRETO -->
<v-btn>{{ t("save") }}</v-btn>           <!-- não resolve: t procura raiz -->
<v-btn>{{ tt("actions.save") }}</v-btn>  <!-- vira modules.<id>.actions.save -->
```

## 🔎 Auditoria

Para evitar colisões acidentais, não duplique chaves genéricas no lang do módulo
quando já existirem no global. Antes de adicionar uma chave local, verifique se
ela já está em `/src/lang` (ex.: `actions.save`, `actions.cancel`, `actions.delete`).
